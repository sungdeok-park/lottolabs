# 로또 워크룸 (개발 중)

내 필터로 로또 6/45 조합을 만들고, 저장·공유한 뒤 추첨 결과까지 확인하는 정적 웹 도구.
당첨을 예측하거나 보장하지 않는다. 기획: `LOTTO-CONTENT-DIFFERENTIATION-PLAN.md`.

## 실행

```
npm install
npm run dev        # 개발 서버
npm test           # 계산 엔진 시험 (전체 8,145,060 열거 포함)
npm run build      # 타입 검사 + 정적 빌드(dist/)
```

## 당첨 이력 데이터

`public/data/draws.json`은 **비어 있다**(실제 데이터를 임의로 만들지 않음). 검증된 출처의 CSV를 준비해 넣는다.

```
node scripts/import-draws.mjs draws.csv "출처 설명"   # 열: round,date,n1..n6,bonus
```

검증에 실패하면 기존 파일을 유지한다. 데이터 공급 경로와 사용 조건은 출시 전에 확인해야 한다.

## 구현 범위

계산 엔진 `src/core` (모두 UI와 분리, 시험 포함):

| 모듈 | 내용 |
|---|---|
| `metrics`, `filters` | 필터 90종 + 회귀 1~200(동시 200개 적용 가능): 기본 12, 번호 특성 12, 분포 22(끝수 0~9·번호대 1~5), 용지 22(가로 1~7·세로 1~7·사용 줄 수·활성 라인·대각선·인접 묶음·공간 패턴), 과거 이력 11(이월·보너스 이월·이웃·핫 N회·콜드 N회·최장 미출현·미출현 합·역대 최대 일치) |
| 회귀 | N회귀 = 목표 회차에서 N회 전 당첨 본번호와 겹치는 개수 (1~200). 원본 회귀분석 페이지(regression.html)의 계산을 옮겨 참조 구현과 대조 시험 |
| 마방진(9궁) | 1~45를 5개씩 9궁으로 나눈 궁별 개수·활성 9궁 수·한 궁 최대. 원본 magic_square 페이지 정의와 무작위 조합 대조, "최근 10회 범위 일괄 적용"도 원본 알고리즘과 대조 |
| 용지 | 원본 lotto_paper 페이지와 같은 7×7 좌표·가로/세로 라인·공간 패턴 분류. 참조 구현과 무작위 20000개 조합 대조 시험 |
| 작업(`jobs`) | 정확한 열거·진단을 Web Worker에서 실행(진행률·취소=워커 종료). 조합 화면 상단에 실시간 조합 수(필터 20개 이하는 자동, 그 이상은 버튼) |
| 필터 진단 | `diagnose`: 규칙별 "이 필터 하나만 끄면 되살아나는 조합 수"와 어긴 규칙 수 분포. 무차별 대입과 대조 시험 |
| 규칙 상태 | 규칙별 켜기/끄기(`enabled`), 회차별 적용·보존(`round`/`preserve`) — 원본 수동필터 동작. 꺼진 규칙은 검증·생성·열거에서 제외 |
| `expr` | 안전한 표현식 해석기 (`sum >= 100 && odd == 3 && !has(7)`). eval 미사용, 길이·깊이·함수 화이트리스트 |
| `filters` 사용자 정의 | 내 번호 집합 필터(집합 내 포함 개수), 표현식 필터 |
| `generate` | 생성(고정/제외/후보·시도 상한·취소·중복 제거), 사전 검증, 정확한 열거(`countSpace`) |
| `enumerate`, `stats` | 전체 열거, 번호별 출현·미출현, 지표 시계열(미래 데이터 제외), 과거 통과율 백테스트, 공간 분포, 조합 묶음 겹침 분석 |
| `wheel` | 축약 휠(그리디 + 전수 검증), 전체 휠. 번호군 최대 16개 |
| `probabilities` | 등수별 정확한 경우의 수·확률 (열거로 교차 검증) |
| `match`, `draws`, `share` | 등수 판정, 당첨 파일 검증, 공유 payload 검증·메일/카톡 본문 |

시험 `npm test`: 선언한 필터 도메인이 전체 8,145,060 조합의 실제 최솟값·최댓값과 일치하는지 전수 확인(약 45초 포함).

화면: 홈, 조합(번호판·필터·수동필터·회귀 1~200 표(개별 ON/OFF·일괄)·과거 통과율·통계·단계별 분석·필터 진단·프리셋), 휠링, 통계, 보관함, 공유 보기, 도움말.

필터 정의는 이 저장소 기준이며 다른 사이트와 다를 수 있다(도움말에 명시). 핫/콜드는 "최근 N회 안에 출현한 번호 수 / 출현하지 않은 번호 수"로 정의했다(다른 사이트 설명 기준, 임시). 

## 미구현 / 확인 필요

- 카카오톡 전용 공유(Kakao 앱·JS 키·도메인 등록 필요, 현재는 OS 공유로 대체)
- 원본(lottoanalysis) 필터 동등성: 회귀·용지·마방진(9궁)은 업로드된 원본 페이지 기준으로 구현(원본 FilterRuleEngine.js 자체는 못 봄). 핫콜드·이월·이웃은 이 저장소 정의 기준
- Web Worker 분리, 생성 개수 상한(현재 임시 500) 성능 시험, PWA, 운영자 제외수, 광고, 해설 콘텐츠 페이지
- 실기기(모바일 공유·mailto 길이) 시험
